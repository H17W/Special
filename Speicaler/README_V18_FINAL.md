# Special v18 — Final Multi-Account Build

هذه النسخة تجمع مزايا النسخ السابقة مع عزل كامل للحسابات المصرح لها.

## أهم ما تم تثبيته
- لوحة مستقلة لكل مستخدم يسمح له المالك بالدخول
- لكل مستخدم قاعدة بيانات مستقلة ووسائط مستقلة ونسخة تقليد مستقلة
- لكل مستخدم جلسة Telethon مستقلة
- تسجيل دخول ذاتي للحساب من داخل البوت
- رقم الهاتف ثم كود Telegram ثم 2FA عند الحاجة
- كود Telegram يقبل الكتابة بالمسافات مثل: `7 7 0 0 0` ويتم تنظيفه داخليًا إلى أرقام فقط قبل إرساله إلى Telegram
- كلمة مرور 2FA لا تُحفظ في قاعدة البيانات ولا في الإعدادات
- جلسة الدخول تحفظ كملف `.session` محليًا ويجب عدم رفعها إلى GitHub
- تسجيل كل محاولة `/start` في سجل دخول البوت للمالك
- صلاحيات ميزات منفصلة لكل مستخدم
- مراقبة الخاص والتعديل والحذف وحفظ الوسائط
- أوامر الكتم بالرد
- `بداية الحذف` و `نهاية الحذف` بدون Slash كما طلب المستخدم
- التقليد للاسم والصورة والبايو واليوزر المشابه مع حفظ الأصل والاستعادة
- إدارة الخاص والمزامنة والاستيراد والبحث والصفحات
- النسخ الاحتياطي والاسترجاع حسب الحساب
- الرسائل المهمة
- الإذاعة والاستثناءات والسجل والجدولة الموجودة في الأساس
- مركز الحماية
- مركز الأمان
- سجل العمليات
- إحصائيات الحساب
- فحص صحة النظام
- إيقاف البوت لا يوقف User Automation
- إعادة الاتصال التلقائي لجلسات Telegram
- الذكاء الاصطناعي لكل حساب وإعداداته وسجله بشكل منفصل

## تصميم الواجهة
تم تنظيف الكيبورد وإزالة الأزرار التي كانت تعرض وحدات غير مكتملة مثل الوحدات الوهمية.

الأزرار الآن مقسمة حسب الوظيفة مع رموز واضحة وحالات 🟢🔴 وأسلوب موحد.

ملاحظة: Telegram Bot API لا يوفر API عام لتغيير لون زر InlineKeyboardButton أو إجبار Emoji متحرك بعينه داخل الزر. لذلك التصميم يستخدم Emoji وحالات مرئية وتخطيطًا موحدًا بدل ادعاء وجود تحكم غير متاح من Telegram.

## العزل
بيانات الحسابات تحفظ داخل:

`storage/accounts/<BOT_USER_ID>/`

وتحتها قاعدة البيانات والجلسة والوسائط وملف التقليد.

قاعدة `special.db` في جذر المشروع مخصصة للتحكم العام مثل المستخدمين المسموحين وسجل دخول البوت.

## التشغيل
1. انسخ `.env.example` إلى `.env`
2. ضع القيم الخاصة بك في `.env`
3. ثبّت المتطلبات من `app/requirements.txt`
4. شغل:

```bash
python -m app.main
```

## ملاحظة أمنية
لا تضع `BOT_TOKEN` أو `API_HASH` أو مفاتيح الذكاء الاصطناعي أو ملفات `.session` في GitHub.
إذا سبق وتم نشر مفتاح سري في مكان عام، قم بتدويره من مزوده.
