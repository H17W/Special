# Special V4 — Granular permissions

هذه النسخة مبنية على نسخة المشروع الحالية وتضيف نظام صلاحيات تفصيلي لكل ميزة فرعية بدل الاكتفاء بالأقسام الرئيسية.

## أهم ما فيها
- أكثر من 90 صلاحية مستقلة في لوحة المطور.
- لكل مستخدم: 🟢 مسموح أو 🔴 ممنوع لكل ميزة.
- زر السماح بكل الميزات ومنع كل الميزات.
- صفحات للصلاحيات حتى لا تصبح لوحة Telegram ضخمة في رسالة واحدة.
- حماية فعلية على callbacks: إخفاء الميزة من القائمة وحدها ليس كافيًا، والـ callback نفسه يرفض إذا كانت الصلاحية ممنوعة.
- إدارة مدد الوصول والحظر والإيقاف.
- إذاعة مع معاينة وتأكيد واستثناءات وسجل.
- نسخ احتياطي كامل ZIP لقاعدة البيانات والـ snapshot والوسائط المحفوظة.
- نسخ احتياطي لمحادثة منفردة.
- أرشفة الرسائل والوسائط وتتبع التعديل والحذف.

## الصلاحيات
القائمة موجودة في `app/core/permissions.py`، ويمكن إضافة أو تعديل أي صلاحية بدون تغيير بنية قاعدة البيانات.

## ملاحظة مهمة
النظام الحالي ما زال يستخدم جلسة Telethon واحدة (`special_user`) للحساب المربوط بالمشروع. لا يتم مشاركة هذه الجلسة تلقائيًا مع المستخدمين المضافين. نظام الحسابات المستقلة لكل مستخدم يحتاج جلسة Telethon مستقلة لكل حساب وربط آمن للحساب، ويفضل QR أو تدفق تسجيل رسمي بدل جمع أكواد Telegram أو كلمات مرور 2FA داخل البوت.

## ميزات تحتاج مزودًا خارجيًا قبل جعلها تنفيذية بالكامل
- تحليل المحتوى الآلي للصور والفيديو.
- رفض نقل الملكية تلقائيًا حسب حدث Telegram المدعوم فعليًا في إصدار Telethon المستخدم.
- جدولة الإذاعة تحتاج worker دائم للتنفيذ في وقتها.
- استرجاع النسخة الاحتياطية يحتاج عملية restore منفصلة مع حماية من الكتابة فوق البيانات الحالية.
